## 目标与命名

推荐 `static.v2grad.com`：名称表达静态资源用途，可容纳图片、字体、脚本及下载文件，后续更换存储或 CDN 也能沿用。当前迁移仅覆盖原图片域名的资源，不同时搬迁本站 CSS、JS 或第三方资源。

| 候选 | 定位 | 取舍 |
| --- | --- | --- |
| static.v2grad.com | 统一静态资源入口 | 推荐，职责清楚、用途宽，长度稍长 |
| assets.v2grad.com | 网站资源入口 | 同样适合长期使用，偏开发者习惯 |
| img.v2grad.com | 图片入口 | 最短、用途直观，但将来放字体或下载不如 static 自然 |
| oss.v2grad.com | 存储产品入口 | 可用，但名称绑定 OSS 实现，与实际经 CDN 分发的职责不完全一致 |

用户已确定采用 `static.v2grad.com`。

## 最终结构

新文章及已更新文章直接使用：

```text
https://static.v2grad.com/img/原文件名.png
    → 阿里云 CDN
    → 原青岛 OSS Bucket 的同一个对象
```

旧入口在兼容期先继续提供原图片；切换稳定后改为：

```text
https://oss.imzhanghao.com/img/原文件名.png?原参数
    → 301
https://static.v2grad.com/img/原文件名.png?原参数
```

不搬文件、不变路径、不改变图片格式和处理参数。新 CDN 源站和回源 Host 都使用原 OSS 源站，不把旧图片域名作为新站源站，防止依赖旧域名及后续重定向循环。

## 分阶段实施

### A：建立新入口，旧入口继续 200

1. 保存旧 CDN 的源站、回源 Host、缓存、参数处理、访问控制、HTTPS 和响应头配置基线，补齐尚未读取的鉴权设置；只复制当前实际需要的设置。
2. 在 CDN 独立添加新加速域名，沿用全球加速、图片小文件和原 OSS 源站。原回源协议和其他有效规则先保持一致，不在换域名时顺带改协议、压缩或格式。
3. 为新域名签发 HTTPS 证书并部署到 CDN；验证域名归属后，把 `static` 的 CNAME 指向 CDN 给新域名分配的目标，TTL 使用 600 秒。不能仅把新域名 CNAME 指向旧图片域名代替 CDN 域名接入。
4. 先核验真实证书、代表图片、HTTP 跳转和 404，再比较全部 361 个新旧 URL。旧地址 200 的资源应在新地址得到 200，Content-Type 与内容保持一致；原本已经失败的旧资源单列，不将其直接归为迁移故障。仅在相同图片处理、压缩条件下比较文件哈希，ETag 作为辅助。
5. 覆盖有无 Referer、v2grad.com 和旧站 Referer、中文/编码路径、已有查询参数与图片处理参数，检查国内及境外 DNS/访问。新域名的浏览器加载不应出现证书、403、跨域或混合内容问题。

本阶段结束条件：新入口验收通过，博客仍引用旧域名。新旧两个入口访问相同对象，不新增一套 OSS 存储。

### B：替换博客引用并发布

1. 仅将实际图片 URL 的主机名从 `oss.imzhanghao.com` 换成确定的新名字，保留路径、查询参数、文章 URL、正文及布局；同时检查生成的图片链接、懒加载字段、Feed、社交分享图和搜索数据。
2. 从空目录隔离构建；检查引用集合、旧图片域名残留和页面资源，证书与私钥仍不进入产物。
3. 发布到 `/var/www/v2grad/releases/<新版本>` 并原子切换 `current`，保留当前已验收版本。不使用会同时推 GitHub、写旧站目录的原 `npm run deploy`。
4. 验收代表文章、图片、懒加载、Feed；记录新 CDN 的 403/404、5xx 和回源状态。新站 361 个基线图片应与阶段 A 一致，原站文章路径不变。
5. 将日常图床或图片上传工具的“链接输出域名”同步为新域名；2026-11-14 已完成 PicList 配置及上传验证，原有文件和上传目录保留。

建议先观察 24～48 小时，再结合实际访问量决定是否进入 C；博客流量较小时不能把“没有错误日志”当作充分验收，仍需主动覆盖基线 URL。

### C：旧图片域名逐个 301 到新域名

优先使用现有 CDN 的 EdgeScript：在旧图片域名模拟环境创建永久跳转规则，测试路径和查询参数完整保留、404 终态正确、无循环后，才发布到生产。普通“重写访问 URL”默认是 302，不能当作永久迁移已完成；EdgeScript 的 rewrite 函数支持指定 301。

2026-11-14 用户已回复“那就做吧”，授权上述阶段 C 的检查、模拟测试及通过后的生产切换，无需再次请求同一范围授权。12:55 核对时，距 11 月 13 日 17:34:59 发布仅约 19 小时 20 分钟；仍遵守已约定的最短 24 小时观察期，不提前生产切换。最早执行时间为 11 月 14 日 17:35（北京时间）。未创建定时任务或后台自动发布。

本次预检：361/361 个新旧图片 HEAD 均返回 200，类型、长度及 ETag 全部一致；新旧 HTTPS 信任链与主机名验证通过，到期时间仍分别为 2027-02-11、2026-12-24 北京时间 07:59:59。证据：/Users/zhanghao/.codex/artifacts/v2grad/static-20261114/pre-301-head.json。该结果是主动请求检查，不等于 CDN 全量访问错误率或境外节点验收。

已通过平台配置、模拟测试并发布的规则（仅旧图片 CDN 域名）：

```text
if eq($host, 'oss.imzhanghao.com') {
    rewrite(concat('https://static.v2grad.com', $request_uri), 'enhance_redirect', 301)
}
```

使用原始 request_uri 保留路径和查询串，enhance_redirect 显式处理完整 URI，响应码明确为 301。模拟与生产均已覆盖 HTTP/HTTPS、中文编码、重复参数、OSS 缩放参数及不存在对象；目标域名直接返回 200 或预期 404，详见上线记录。回退时停用本次新增规则、恢复原入口 200，保留规则与现有源站配置；不删除资源，不把新域名反向跳回旧域名。

新 CDN 域名不能套用这条旧域名跳转规则。此阶段不删除 OSS 对象、旧 CDN 配置或原证书。旧入口 HTTPS 必须继续有效，先握手成功才能发送 301。

若实施时发现现有账号的 EdgeScript 无法满足该规则或需新增付费能力，先报告具体限制；可复用当前 Nginx 专门承接旧图片域名的 301，另行准备该域名证书及 DNS 切换，不把 302 当作默认替代方案。

无需对图片子域名再执行一次 Search Console“网站地址更改”。通过文章内的新图片链接、正常抓取及旧图片 301 让搜索引擎逐步处理；不以站点地图提交成功表示图片搜索已迁移完成。

## 回退

- A 阶段失败：旧站和旧图片入口保持原样，停止引用切换；保留已经建立的新配置以便排查。
- B 阶段失败、尚未启用旧图片 301：把博客 current 切回前一个版本，继续使用旧图片入口。
- C 阶段失败：优先恢复新图片服务，因为客户端可能缓存旧入口的 301。必要时将旧 CDN 边缘规则回退到兼容的 200；若新入口不能修复，可让新入口继续从原 OSS 提供内容，再回退博客版本。不能把新入口反向 301 回旧入口，防止循环。
- 全程保留原 OSS 对象，回退不需要复制或覆盖存储数据。

## 旧域名退出条件

图片新入口发布验收完成后，博客自身可不再依赖旧图片主机名，但历史外链和搜索中的旧图片仍需要兼容。旧主站的文字页面迁移也仍在观察中，不能以图片切换完成替代整个旧域名的退出验收。

建议旧图片永久跳转至少保留一年；若 C 阶段晚于 2026-11-13 执行，按实际启用时间计算，旧注册域名到期安排也需覆盖该兼容期。旧图片证书须在 2026-12-24 到期前续签或更换，并继续维护。已确认无在用引用、历史入口访问可接受且明确接受旧外链失效后，再决定是否不续费旧域名。
